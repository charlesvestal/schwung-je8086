- **The perf load path is fine.** `child_serve_load` re-addresses the whole
  performance, common block included, into temp (`jp8000_plugin.cpp:968-971`),
  which is why the device shows Arp = ON.
- **"Reads back ON" proves our IMAGE, not the firmware's behaviour.** Every arp
  read comes from our own temp image, which we wrote. It is not evidence.
- **`set_param("mode")` does nothing to the device.** `jp8000_plugin.cpp:735`
  says so: "`mode` is a UI fact (which browser is shown)"; `:1664` only assigns
  `inst->mode`. Charles's recollection is that Patch/Perform are edit modes and
  parts are always Upper/Lower, so this may be irrelevant — but it is real.
- **No system parameter is exposed or written.** 0 of our 169 are system.
  `PerformanceControlChannel` is system index 2 (`jemiditypes.h:61`);
  `RemoteControlChannel` is index 9. Charles: default is 16, and **forwarding to
  16 plays no notes**, which reproduces in the emulator (ch 16 silent).
- **The ASIC split is not implicated.** Everything above was measured in the
  plain serial `jeLib::Je8086` path with no fork pipeline present at all.
- Temp-area DT1 writes DO reach the firmware: control, `cutoff` 0 vs 127, max
  sample diff 1 772 267 and RMS 126k vs 366k. There is **no equivalent control
  for the SYSTEM area** — my system writes are unverified.

## Two wrong claims I made, and why

## Instrument first (the method constraint)

**Audio onset detection does not work here, and it is not a tuning problem.**
Chariots has a soft attack, a long release and a delay tail. Measured: a real
note-on at 6.5 s gives spectral flux 21.5 against a running background of ~15 —
no peak. `src/tools/jp_onsets.py` exists but is the weaker tool.

**Use `src/tools/jp_voice_onsets.py`.** `JP_UC_LOG=<path>` makes `jp8000_render`
dump per-128-sample-block counts of H8S→ASIC writes, bucketed by
`(asic, addr >> 8)`. The firmware programs a voice region when it starts a note,
so a rising edge out of a silent bucket **is** a note start. Positive control of
three separately scripted notes: **exactly 3, at 5.002 / 6.502 / 8.002 s.**

New `jp8000_render` env: `JP_UC_LOG`, `JP_LCD_LOG`, `JP_SYSEX_LOG`.
New script verbs: `clock_bpm`, `start`/`stop`/`continue`, `sysparam`, `sysreq`,
`perfreq`, `perfcommon`, `snapshot`.

**LEDs are not available**: `Port::lits` / `Port::litnames` are declared in
`je8086devices.h` and defined nowhere, so `getLed()` cannot link.

## A harness bug that had hidden itself

`jeLib::Device` reads the battery RAM at **`homePath + "/roms/ram_dump.bin"`** —
`homePath` is the PARENT of the rom dir. We passed the rom dir, so the RAM was
never found and `m_factoryreset` was true on every construction. The `Je8086`
ctor **returns early** from `runfactoryreset()`, leaving `postSample`, the MIDI
rate limiter and both LCD callbacks unbound → `std::bad_function_call`.
`loadSnapshot()` rebinds all of them, which is the only reason the snapshot path
worked. **Cold boot had never been runnable, and every run was on a
factory-reset RAM.** Fixed.

## Ground truth, read from the firmware

System area (`sysreq`): `PerfControlChannel=0F(ch16) MidiSync=00 LocalSwitch=01
TxRxEditMode=00 TxRxEditSwitch=00 TxRxPCSwitch=02 RemoteControlChannel=11
MasterTune=32`.

**System writes land** — write then read back: PCC `0F→02`, MidiSync `00→01`,
TxRxEditSwitch `00→01`, MasterTune `32→64`. This closes resume-item 2.
**TxRxEditSwitch is not a prerequisite** (verified: RemoteControlChannel set with
no TxRx writes at all still gives the arp). I briefly thought it was a gate; the
earlier null sweep failed because the performance control channel carries no
notes, which is the next paragraph.

**The performance control channel carries no notes** — set it to any value and
play the matching channel: zero voices. Notes reach only `Part::MidiChannel`
(Upper=ch1, Lower=ch2). The JUCE plugin's "channel 3" is
`getPartsForMidiChannel`'s hardcoded `_channel == 2` remote case: **parameter**
routing, as resume-item 1 suspected.

Chariots' temp performance (`perfreq`): **ArpSwitch=1, ArpeggioDestination=1
(LOWER), Mode=2 (UP&DOWN), BeatPattern=4, OctRange=0, Hold=1, Tempo=74 BPM**,
KeyMode=2 (SPLIT, point 56). Charles was right about both the arp and the lower
part. **Tempo is 14-bit at 0x22/0x23** — reading only 0x22 says "0", which is
wrong; I made that mistake mid-session.

**The firmware's internal clock runs**: the ROM demo (hold `kSwitch_Rec` +
`kSwitch_Hold` and never release, jeTestConsole's trigger) plays — −90 dB →
−10 dB, sustained 20 s.

**Panel injection works**: `button 72` (PerformSel) flips the LCD to

## SOLVED — the arp is fed only by the Remote Control Channel

**The JP-8000 has two note paths and only one reaches the arpeggiator.**

- A note on a part's own `Part::MidiChannel` (Upper=ch1, Lower=ch2) goes
  **straight to that part's voices** — bypassing the arpeggiator, and also
  bypassing KeyMode (split/dual) and the panel selection.
- A note on the **`RemoteControlChannel`** (system parameter 9) enters the "as if
  played on the panel keyboard" path. **Only that path feeds the arp.**

The firmware default is `0x11` = **Off**, and `child_boot_force_system` set six
system params without ever setting this one. `jeController::parseSystemParameters`
does set it ("Set remote channel to 3") — the whole difference, and the origin of
Charles's "channel 3".

| RemoteControlChannel | notes on | voice starts |
|---|---|---|
| 17 (Off, the default) | any | 1 |
| 0 / 1 / 2 (ch1/2/3) | matching channel | **31** |
| 16 (All) | ch3, ch5, ch9 | **31** |
| 2 (ch3) | ch1, ch2, ch4 | 1, 2, 0 — none |

31 starts at a dead-regular **0.405 s** — an eighth note at the stored Tempo=74
BPM, continuing past note-off because `ArpeggioHold=1`. The rate matching the
stored tempo is the independent confirmation this is the real arpeggiator.

The remote path takes the note **instead of** the part, so nothing
double-triggers. With the arp off, remote-channel notes still play — but now
through the keyboard path, so the split applies (notes below Chariots' split
point 56 land on Lower rather than Upper). Correct hardware behaviour, and a
behaviour change for anyone addressing Upper/Lower by channel.

Also ruled out along the way, each with a measurement: `KeyScanner` (a permanent
stub; `JP_KEYSCAN=0` vs `0xFF` identical), faders (default 512, no `setFader`),
MIDI clock, MidiSync, and the arp's own panel buttons.

## The fix

`jp8000_plugin.cpp` `child_boot_force_system` also sends
**`RemoteControlChannel = 16` (All)** and `PerformanceControlChannel = 0x11`
(off, as the editor does). `src/module.json` keeps
`"default_forward_channel": 1`.

**The first attempt used channel 3, like the JUCE editor, and FAILED on the
device.** Channel 3 needs the slot to forward there, and on Move that cannot be
relied on:

- **"Auto" does not mean "ask the module" — it means "use the receive
  channel".** `shadow_chain_remap_channel` (`shadow_midi.c:216`) returns the
  *receive* channel for `forward_channel == -1`, so an Auto slot with receive=1
  forwards on **ch1**.
- `capabilities.default_forward_channel` only **pre-seeds** `forward_channel` at
  four load call sites in `shadow_chain_mgmt.c`, and only while it is still -1.
  It never reaches the remap function.
- A MIDI FX ahead of the synth can rewrite the channel again.

"All" makes all three irrelevant: whatever channel the note arrives on reaches
the arpeggiator. Cost: Upper/Lower can no longer be addressed on separate MIDI
channels — notes take the keyboard path, where the performance's own KeyMode
picks the part. Hardware behaviour, and what makes Chariots' split correct.

## Verified on Move hardware

`plugin_drive` against the deployed `dsp.so` — this exercises
`child_boot_force_system`, which `jp8000_render` does not. One held note,
envelope attack count:

| | attacks | first intervals |
|---|---|---|
| before, ch1 | 0 | — |
| after, ch1 / ch2 / ch3 | **11 each** | 0.40 / 0.40 / 0.42 s |

0.40 s is an eighth note at Chariots' Tempo=74. **0 underruns** on every run.
`plugin_drive` gained `JE_DRIVE_CH` (pin a 0-based channel) and `JE_DRIVE_NOTES`
(trim the 8-note chord — one note makes the arp unmistakable, eight are a wash).

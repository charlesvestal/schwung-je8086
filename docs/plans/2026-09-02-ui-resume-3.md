## The list-page bug: diagnosed, and it was never a bug in the new code

The screen Charles saw was **not** the shadow preset browser. It was the
STANDALONE editor — `src/ui.js` -> schwung's
`src/shared/sound_generator_ui.mjs`, `drawUI()` at :317. Every line maps:

| Screen  | Source                          | Needed          |
|---------|---------------------------------|-----------------|
| JP-8000 | `print(2,2,moduleName)`         | —               |
| `0`     | bank line, `state.bankName`     | `bank_name`="0" |
| `#1/1`  | `#${patchInBank}/${presetCount}`| both "0" -> `parseInt("0")\|\|1` = 1 |
| `0`     | `state.presetName`              | `preset_name`="0" |
| `------`| `fill_rect` — the LOAD-ERROR rule | `load_error` truthy |
| `0`     | wrapped error text              | `load_error`="0" |

Every field is the string `"0"`. Exactly one build ever did that — a196b4e,
whose `v2_get_param` ended in `return snprintf(buf, buf_len, "0");` for every
unknown key. HEAD returns -1, which `schwung_host.c:1513` turns into JS
`undefined`, so the new build **cannot** draw that page.

**The device was running the OLD dsp.so.** `MoveOriginal` pid 31100 had been
up 3 h 26 m (since ~06:52 device time); the new `dsp.so` landed at 10:07.
`mv`-over-the-file never swaps an already-`dlopen`'d library. Lead #1 in
resume-2 was right; leads 2–5 were chasing the wrong surface.

Note for the standing rules: "a reload DOES pick up the new plugin" holds only
if the slot is genuinely unloaded first (`module_manager.c:602` does dlclose).
It did not happen here. **Check `ps -o etime` on pid-of-MoveOriginal against
the dsp.so mtime before trusting any device result.**

## The second, real bug — fixed

Even loaded correctly, the new build would have shown `#1/1 / Init`: the
plugin implemented NONE of the unified vocabulary the shared UI reads. Added
to `jp8000_plugin.cpp`, mirroring `schwung-virus/src/dsp/virus_plugin.cpp:2812`:

- `jp_selection()` — one mode-aware view (`inst->mode`) onto the state the
  hierarchy keys already own, so Patch mode browses patches and Performance
  mode browses performances with no second copy to drift.
- get_param: `bank_index` `bank_count` `bank_name` `preset` `preset_count`
  `preset_name` `patch_in_bank` `octave_transpose` `name`, plus `load_error`
  answered AHEAD of the `ui_ready` gate (a ROM that will not load never lets
  `ui_ready` rise, and the error box is the only place the reason shows).
- set_param: `preset` / `bank_index` delegate to `patch`/`performance` and
  `bank`/`perf_bank`; `octave_transpose`; `all_notes_off` (ch 1+2).
- `v2_on_midi` applies the octave to note bytes, dropping out-of-range notes.
- `state_get`/`state_apply` persist `octave_transpose` (sentinel -99, since
  the value is signed). Blob still `"version":1` — parsing is field-wise.
- `ui.js`: `showOctave: true` (Up/Down drive `setOctave` unconditionally in
  the shared UI, so the state existed but was invisible).

**Also fixed, same class:** `v2_get_param`'s guard returned `0`, not `-1`.
`js_host_module_get_param` builds the string from `buf` and IGNORES the length,
so any `>=0` return that leaves `buf` unwritten hands JS whatever was on that
stack slot. Only -1 reaches JS as `undefined`.

## Where "all the parameters" live

Not in `ui.js`, on any path. `page_controller.mjs` is imported only from
schwung's `src/shadow/` and `chain_editor_chrome.mjs` — the full-parameter
surface is the **Signal Chain slot editor**, fed by `ui_hierarchy` +
`chain_params`, which jp8000 already serves. Standalone `ui.js` is a preset
browser, exactly as in schwung-virus. A jv880-style hand-written UI would only
duplicate the param pages.

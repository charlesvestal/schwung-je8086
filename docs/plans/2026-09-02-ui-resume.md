## JP-8000 SysEx facts (verified against jeLib)

- DT1: `F0 41 10 00 06 12 a0 a1 a2 a3 data.. cs F7`;
  `cs = (128 − (sum(addr+data) & 0x7f)) & 0x7f`.
- Addresses are PACKED 7-bit/byte. `linear = ((packed>>8)&0x7f)*128 + (packed&0x7f)`;
  `packed = ((lin/128)<<8) | (lin%128)`. `jp8000_params.h` `lin` is the
  LINEAR byte offset (verified: `ctl_amp_lfo1_depth` lin 0x80 == packed 0x100).
- Areas: System `0x00000000`; PerformanceTemp `0x01000000` — Common +0x0000
  (36 B), PartUpper +0x1000 / PartLower +0x1100 (7 B each), PatchUpper
  +0x4000 / PatchLower +0x4200 (239 B each), block mask 0xFF00; UserPatch
  `0x02000000` (stride packed 0x200, bank B at +0x10000, local mask 0x1FF);
  UserPerformance `0x03000000` (stride 0x10000, local mask 0xFFFF).
- 14-bit values: MSB then LSB at consecutive linear offsets
  (`PerformanceCommon::Tempo` = 0x22, `IndividualTriggerSourceNote` = 0x20).
- Part enum: PatchBank 0, PatchNo 1, MidiChannel 2, PartTranspose 3,
  DelaySync 4, LfoSync 5, ChorusSync 6.
- Bank Select MSB 80 user / 81 preset; patches PC 0–127, performances
  PC 0–63 on the Performance Control Channel (ch16 as tested).
- **Load pattern** (JUCE `Controller::sendSingle`, jeController.cpp 546–609):
  for each message of a preset — patch → re-address to
  `Temp | PatchUpper/PatchLower | (addr & 0x1FF)`; performance →
  `Temp | (addr & 0xFFFF)`; fix checksum (`jpbank::dt1_set_addr` does both);
  send; then `State::createPerformanceRequest(PerformanceTemp, UserPerformance01)`
  to re-read the temp area. Replies come back as DT1s via
  `je->readMidiOut(std::vector<synthLib::SMidiEvent>&)`, `.sysex` filled.
  Send via `je->addMidiEvent` with an `SMidiEvent` whose `.sysex` is set.
- **System forcing at boot** (JUCE `parseSystemParameters`, we differ in two):
  `TxRxEditSwitch=1, TxRxEditMode=1, LocalSwitch=1, MidiSync=1,
  KeyboardShift=2, TxRxProgramChangeSwitch=2` (Bank Sel + PC — JUCE uses 0),
  and KEEP our `PerformanceControlChannel` (JUCE sets 0x11 = off).
  `SystemParameter` enum order: PerformanceBank, PerformanceNumber,
  PerformanceControlChannel, PowerUpMode, MidiSync, LocalSwitch, TxRxEditMode,
  TxRxEditSwitch, TxRxProgramChangeSwitch, RemoteControlChannel, MasterTune, …,
  KeyboardShift(20), RibbonRelative, RibbonHold.
- jeLib statics: `State::getAddress` (packed 32-bit), `setAddress`,
  `updateChecksum`, `createParameterChange(SystemParameter, v)`,
  `createPerformanceRequest(area, perfArea)`, `createSystemRequest()`.
- Factory presets: `jeLib::Rom::getPresets(std::vector<std::vector<Preset>>&)`
  → [0] patches A11–A88 (64), [1] B11–B88 (64), [2] performances (64); each
  `Preset = std::vector<Sysex>` of DT1s addressed to UserPatch/UserPerf.
  **Always returns false (bug) — ignore it, check sizes.**

## `jpbank` API (`src/dsp/jp8000_banks.h`)

`Msg = std::vector<uint8_t>`; `Preset {name, msgs}`; `Bank {name, is_perf, presets}`.
`packed_to_linear`, `linear_to_packed`, `checksum`, `make_dt1(addr,data,n)`,
`is_dt1`, `dt1_addr`, `dt1_data_len`, `dt1_data`, `dt1_set_addr(m, addr)`,
`raw_sysex`, `smf_sysex` (MThd/MTrk, VLQ, F0/F7 continuation, running status),
`classify(msgs, patches, perfs)` (groups by area+program in first-appearance
order; a message running past the 239-byte temp patch — JP-8080 240/242 B
dumps, also inside a perf's 0x4000/0x4200 blocks — is CUT at the boundary,
one wholly past it is dropped), `parse_pat` (WinJPLib "JP-8000 USER PATCH",
128 patches), `parse_pfm` ("JP-8000 USER PERF", 64 perfs → 5 DT1s each),
`scan_file` (.pat .pfm .syx .j8k .mid .midi; ≤2 banks per file, patches and
perfs, both named after the file), `scan_dir(dir, banks, name_max=23)`
(non-recursive on purpose — it is the device's `banks/` dir, sorted by name).
Sequence-only `.mid` files (Q-Trilogy, Waldorf, "JP Eternal MIDI") give 0 banks.

  + links perf_setup/perf_upper/perf_lower/perf_arp/perf_trigger), …
- minijv (schwung-jv880) is the model — not prescriptive.

## The converged design (not yet coded)

1. **SysEx ring parent→child** in SHM: `sx_buf[16384]`, `sx_read/sx_write`,
   2-byte length prefix. Child drains each into an `SMidiEvent` (`.sysex`)
   and `addMidiEvent`s it from the main loop.
2. **Value mirror = raw linear images in SHM**: `img_common[64]`,
   `img_part[2][16]`, `img_patch[2][256]`, `img_system[32]`, `img_valid`
   bits, `img_seq`. Child drains `readMidiOut()` and copies PerformanceTemp /
   System DT1 data to `packed_to_linear(addr & submask)`. Parent reads O(1):
   `raw = img[lin]` (14-bit `(img[lin]<<7)|img[lin+1]`); value = raw − off,
   or −raw when `neg`; enum index = raw − off. Writes optimistically on set.
3. **Boot**: system forcing + `createSystemRequest()` +
   `createPerformanceRequest(PerformanceTemp, UserPerformance01)` at the START
   of the 2 s warm-up loop (761–772), draining there so images are valid before
   the stages fork. Keep draining in the main loop for later re-requests.
4. **`v2_set_param` on the SPI thread**: build the DT1 in a stack buffer (no
   std::vector), push to the sx ring, update the image; `part` Both → both
   patch areas. Program Change goes through the MIDI FIFO; child schedules a
   temp re-request ~100–200 ms later (also after every preset load).
5. **Presets**: child builds `std::vector<jpbank::Bank>` = factory
   ("Factory A"/"Factory B" patches, "Factory" perfs from `rom.getPresets`) +
   `jpbank::scan_dir("<module_dir>/banks")`. SHM: `patch_bank_count`,
   `patch_bank_names[JP_MAX_BANKS=32][24]`, `patch_bank_sizes`; same for perf;
   name tables `patch_names[128][17]` / `perf_names[128][17]` for the CURRENT
   bank, filled by the child when `patch_bank_req != patch_bank_cur` (parent
   returns -1 for `patch_name:N` until `cur` matches); load request fields
   `load_seq/load_done/load_kind/load_bank/load_index/load_part` (0 upper,
   1 lower, 2 both). Child replays with `dt1_set_addr`, then re-requests temp.
   Bank list must be in SHM BEFORE `child_ready` so `chain_params` = prefix +
   `{"key":"bank",…enum of patch banks}` + `{"key":"perf_bank",…}` + `]`;
   -1 while not ready.
6. **Parent UI state** in `jp8000_instance_t`: mode (0/1; get answers
   "Patch"/"Performance", set accepts index or name), part (0/1/2), bank,
   patch, perf_bank, performance. `mode` is UI-only (nothing sent; PanelSelect
   left alone).
7. **`state` blob**: JSON `{"mode","part","bank","patch","perf_bank",
   "performance","temp":"<hex of common36+partU7+partL7+patchU239+patchL239 = 528 B>"}`.
   Set = split into 5 DT1s → sx ring + images; if `!child_ready` store as
   `pending_state`, applied from the boot thread after `fork_and_wait_child`.
   Get returns -1 until images valid.
8. Keep `__status`; `__ui` can stay.
